# 写作质量评测方法

固定用例位于 `backend/evals/writing_quality_cases.json`。对照评测必须使用相同模型、参数、用户要求、上传材料和KnG开关，分别运行当前基线与候选Skill版本。

先检查硬失败项；任一无依据事实、明确事项遗漏、排除项回流或材料角色越界均判为不通过。通过硬门槛后，再按事实忠实度、事项覆盖、文体正确性、结构自然度、高校行政语言和生成式套话六项评分。

第三方规则按“官方规范基础 → 结构及事实规则 → 降套话规则 → 最终组合”依次加入。只有事实安全不下降，且语言或结构评分稳定提高的规则才能进入正式Skill。每种文体至少抽取3篇人工复核；模型评分只作辅助，不能替代人工判断。

参考写作除正文质量外，还要核对运行结果中的 `workflow_plan.material_plan`：用户指定的主次和用途必须被执行，只有内容材料摘录可以提供正文事实，多材料结果不得表现为摘要拼接。
