# 任务路由

本文件用于判断用户任务应走哪类文种、是否需要追问、是否需要检索北航本地材料，以及最终输出正文还是审查意见。

## 先判断任务类型

1. 起草：写一份、起草、拟一个、生成、形成某类公文或材料。
2. 改写：把初稿改正式、润色、压缩、扩写、转成公文语体。
3. 整理：根据会议记录、要点、清单、材料包整理成正文。
4. 审查：检查、把关、看看有没有问题、是否符合公文要求。
5. 输出正文：用户要求直接给正文、Markdown、Word 内容或可下载文件。

## 再判断文种

按用户目的优先判断，不只看标题关键词：

- 布置工作、告知事项、报送材料、组织会议、印发制度：读取 `doc_types/notice.md`。
- 向学校、校领导、上级单位请求批准或协调支持：读取 `doc_types/request.md`。
- 汇报工作情况、办理情况、问题和建议，但不要求批复：读取 `doc_types/report.md`。
- 不相隶属单位商洽、询问、邀请、征求意见、回复来函：读取 `doc_types/letter.md`。
- 根据会议记录形成议题、意见、议定事项：读取 `doc_types/minutes.md`。
- 起草管理办法、规定、实施细则、议事规则、章程：读取 `doc_types/regulation.md`。
- 起草实施方案、行动方案、专项工作方案：读取 `doc_types/plan.md`。
- 起草指导意见、实施意见、若干意见：读取 `doc_types/opinion.md`。
- 起草工作总结、工作要点、年度计划、重点工作计划：读取 `doc_types/summary_plan.md`。
- 起草通报、公示、公告、通告：读取 `doc_types/bulletin_publicity.md`。
- 起草批复、决定、决议等低频正式文种：读取 `doc_types/decision_approval.md`。
- 起草征求意见情况报告或制度送审说明：读取 `doc_types/consultation_report.md`。
- 写新闻类文章、网站稿、活动报道、宣传稿：读取 `doc_types/news.md`。

如用户文种和目的冲突，以目的提示风险。例如用户说“写报告申请经费”，应提示“有明确申请批准事项，更接近请示”。

## 复杂度处理

简单任务：

- 会议通知、活动通知、时间地点变更、短函、短提醒。
- 用户已给对象、事项、时间、要求。

处理方式：读取北航语境、事实约束和对应文种，直接输出正文；缺 1 个关键字段时先问。

常规任务：

- 普通通知、请示、报告、函、会议纪要、总结计划。
- 用户给出主题和部分材料，但结构未整理。

处理方式：最多追问 3 个关键问题；如可用待补项承接，不必阻断；生成正文后简短列出需确认事项。

高风险任务：

- 请示、复函、制度办法、会议纪要、经费、岗位编制、人事、招生、学位、安全、保密、意识形态、纪律处分、正式对外承诺。

处理方式：读取审查清单；事实、依据和权限不足时不得写确定结论。必要时先输出待确认清单，再起草审慎稿。

## 追问规则

只追问会影响方向、对象、结论或风险的信息：

- 发文主体、主送对象不明，且会影响称谓或责任边界。
- 请示事项、申请金额、审批对象、拟请解决事项不明。
- 会议纪要缺会议时间、议题、议定事项或材料只给参会名单。
- 制度类缺适用范围、职责主体、程序规则或依据。
- 函/复函缺来函事项，无法逐项回应。

不要为了完整而追问所有格式字段。文号、签发人、印章、版记、页码等交给外层流程。

## 检索规则

写作时按下列事实优先级处理材料：

1. 用户本轮材料。
2. 用户上传文件。
3. 北航本地历史制度和历史文稿。
4. 用户明确授权的外部检索结果。
5. 通用文种知识。

第 5 类只能提供结构，不得提供具体事实。北航本地知识库命中内容也不能自动升级为当前任务事实；除非用户要求参考或材料确实适用。
