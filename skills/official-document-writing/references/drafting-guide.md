# 通用公文起草指南

## 共同要求

- 标题准确包含事由和文种；未知发文机关时不要杜撰。
- 正文先说明必要缘由，再写核心事项；每段集中表达一层意思。
- 层级使用“一、”“（一）”“1.”“（1）”，不使用 Markdown 项目符号代替公文序号。
- 语言准确、平实、简明、庄重，避免口号堆叠、绝对化承诺和空泛形容。
- 人名、单位、政策、数字、时间、地点、权限和成果必须来自用户或证据。

## 文种骨架

- 请示：背景和依据—现实问题—单一请示事项—“妥否，请批示”。
- 报告：基本情况—主要工作或问题—后续安排—“特此报告”；不提出需批准事项。
- 函：发函缘由—商洽、询问或答复事项—与语义一致的期复语。
- 批复：引用来文—明确答复—执行要求；没有来文信息时不得编造文号。
- 纪要：会议基本信息（仅限已知）—议定事项—责任与时限（仅限已知）。
- 决定：作出决定的事实与依据—决定事项—执行要求。
- 意见或方案：总体要求—主要任务—职责分工—保障措施；规模应服从用户材料。
- 总结或报告材料：基本情况—工作成效—存在问题—下一步安排；没有数据时用定性表述。

## 缺失信息

缺失主送机关、落款或日期不影响主体起草时可以省略；若用户明确要求完整格式，可使用“待补充”标识。不得用看似真实的示例值填充。
