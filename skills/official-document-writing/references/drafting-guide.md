# 通用公文起草指南

## 事实纪律

- 事实来源优先级：用户本轮要求、用户上传文件、明确适用的知识库证据、用户授权的外部检索结果、通用文种知识。
- 通用文种知识只能提供结构和语气，不提供具体事实。
- 材料已给且与任务相关的事实，保持主体、对象、数字、时间、状态和结论强度。
- 材料写“拟、建议、研究中、待确认、可考虑”时，正文不得升级为“已决定、必须、已经完成、形成机制”。
- 材料未谈的责任单位、完成时限、审批结论、经费安排、人员名单、附件名称和后续措施，不为完整而补写。
- 具体政策、制度名称、文号、日期、金额、人数、比例、排名、联系方式必须有来源。

## 起草方法

1. 先确定文种、读者、发文目的和必须覆盖事项，再决定结构。
2. 标题准确包含事由和文种；未知发文机关时不杜撰。
3. 正文每段承担一个主要功能，如背景、依据、问题、事项、责任、时限、反馈或结语。
4. 复杂事项使用“一、”“（一）”“1.”“（1）”层级；简单事项可连续行文，不强凑三段式。
5. 任务段落尽量写清谁负责、做什么、针对什么对象、何时完成、如何报送或反馈；材料没有的要素省略或以醒目待补项提示。
6. 结尾回到责任、时限、报送、反馈或审慎结论，避免宣传式升华。

## 文种骨架

- 请示：背景依据、现实问题、单一请示事项、妥否请批示。
- 报告：基本情况、主要工作或问题、后续安排、特此报告；不提出需批准事项。
- 函：发函缘由、商洽/询问/答复事项、与语义一致的期复语。
- 批复：引用来文、明确答复、执行要求；无来文信息时不编文号。
- 纪要：会议基本信息、研究事项、议定事项、责任和时限；只写材料已给内容。
- 意见或方案：总体要求、主要任务、职责分工、保障措施；规模服从用户材料。
- 总结或汇报：基本情况、工作成效、问题不足、下一步安排；没有数据时用定性表述。

## 参考写作

- 内容材料提供事实，结构材料提供章节顺序和段落功能，风格材料提供语气和节奏，背景材料只帮助理解。
- 一个文件作骨架、其他文件补内容时，先复用骨架的段落功能，再替换新事实；不要把多份材料摘要拼接。
- 如果用户要求“尽量使用原文”“只改变化部分”“以前一版为底稿”，按底稿修订处理：输出完整正文，未被明确要求修改的段落、附件和落款默认保留。
- 结构或风格来源中的旧人名、单位、日期、数字、职责和旧任务结论不得进入新稿事实。
- 材料冲突且用户未指定优先级时，不自行择一；省略争议信息或用中性表达并提示核对。

## 改写修订

- 以最新版正文为主线，去口语化、理顺结构、压实表达，不新增原文没有的事实。
- 压缩时先锁定不可丢要素：主体、对象、数字、期限、责任、附件、联系人、反馈渠道、请批事项、落款单位和日期。
- 选区修改只输出选区替换内容，不改选区外事实和结构。

## 输出边界

正文中不得写来源说明、审查意见、检索日志、写作过程、代码围栏、Markdown 加粗、分割线、旧协议标记或“供参考”引导语。字体字号、页边距、印章和版记不在 Markdown 中伪造。
